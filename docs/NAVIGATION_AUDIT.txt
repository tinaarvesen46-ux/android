SWIFTSNAP - NAVIGATION AUDIT
============================

PRIMARY NAVIGATION (lib/widgets/common/snap_bottom_nav.dart)
  [ MAP ] [ CHAT ] [ CAMERA ] [ DISCOVER ] [ REELS ]
  The camera is the centre item INSIDE the nav container, never a floating
  action button. Profile is deliberately NOT a tab.
  Branch state is preserved by StatefulShellRoute.indexedStack.

SHELL ROUTES
  /map  /chats  /camera  /discover  /reels

PROFILE ACCESS (contextual, from every relevant surface)
  Chat header action            -> /profile
  Discover header               -> /profile
  Chat row long-press sheet     -> /user/{id}
  Map friend marker sheet       -> /user/{id}
  Reels creator + more sheet    -> /user/{id}
  Search result                 -> /user/{id}
  Friends list and requests     -> /user/{id}
  Notification actor            -> /user/{id}
  Blocked list                  -> /user/{id}

DETAIL ROUTES
  /capture (extra: CaptureDraft)   /story (extra: Story)
  /article/{id} (extra: DiscoverItem)   /chat/{id}   /user/{id}
  /profile   /profile/edit   /avatar   /friends   /notifications
  /search    /memories       /achievements   /creator   /swiftplus
  /settings  /settings/{section}
  /settings-blocked   /settings-permissions   /settings-about

AUTH ROUTES
  /  (session probe)  ->  /login  ->  /register (5 steps)  ->  /chats
  Register step order: 1 name/surname · 2 birthday · 3 username ·
  4 password · 5 email.
  Login accepts a username OR an email in a single identifier field.

DEAD-UI POLICY
  No `onTap: () {}` remains. Every control either performs a real action,
  navigates, or states plainly that it needs a backend endpoint. Actions that
  depend on a missing endpoint are surfaced as an explicit message, never as a
  silent no-op and never as a fake success.

BACK BEHAVIOUR
  Detail routes are pushed and honour the system back gesture. Tapping the
  active tab returns that branch to its root. The shell is never popped.
  Register steps pop one page at a time and preserve entered values.
