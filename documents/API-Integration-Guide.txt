VibeChat Laravel backend API. All API infrastructure is
located in lib/api/.

FILE STRUCTURE:
  lib/api/
    api_config.dart          - Endpoint constants
    api_client.dart          - Dio HTTP client with interceptors
    api_response.dart        - Typed response wrapper
    services/
      auth_service.dart      - Authentication operations
      user_service.dart      - User profile & search
      chat_service.dart      - Conversations & messages
      story_service.dart     - Story CRUD & feed
      friend_service.dart    - Friend requests & management
      settings_service.dart  - User settings & preferences
      admin_service.dart     - Admin panel operations

STEP 2: AUTHENTICATION FLOW (UPDATED v2.0)
================================================================

HOW IT WORKS NOW:
  - main.dart renders AuthGate which watches AppProvider.isLoggedIn
  - isLoggedIn = false  →  LoginScreen is shown
  - isLoggedIn = true   →  HomeScreen is shown
  - No Navigator pushes needed — state drives routing automatically

LOGIN FLOW:
  1. User enters email/password on LoginScreen
  2. Call: AuthService.login(email, password)
  3. Backend returns: { user: {...}, access_token: '...', refresh_token: '...' }
  4. Store tokens: flutter_secure_storage.write('access_token', token)
  5. Call: Provider.of<AppProvider>(context, listen: false).login(userModel)
  6. AppProvider sets isLoggedIn = true → AuthGate re-routes to HomeScreen

LOGOUT FLOW:
  1. User taps Log Out in Profile tab (confirmation dialog shown)
  2. Call: AuthService.logout()  (invalidates server session)
  3. Clear tokens: flutter_secure_storage.deleteAll()
  4. Call: Provider.of<AppProvider>(context, listen: false).logout()
  5. AppProvider sets isLoggedIn = false → AuthGate re-routes to LoginScreen

REGISTER FLOW (3 STEPS):
  Step 1 — Collect: firstName, lastName, username, password, birthday
  Step 2 — Collect: email OR phone number (user picks one)
    POST /auth/otp/send
    Body: { "identifier": "email@example.com", "type": "email", "purpose": "registration" }
  Step 3 — Verify OTP:
    POST /auth/otp/verify
    Body: { "identifier": "email@example.com", "code": "123456", "purpose": "registration" }
  On success → POST /auth/register with all collected data

FORGOT PASSWORD FLOW (3 STEPS):
  Step 1 — User enters email or phone:
    POST /auth/password/forgot
    Body: { "identifier": "email@example.com", "type": "email" }
  Step 2 — User enters OTP:
    POST /auth/otp/verify
    Body: { "identifier": "email@example.com", "code": "123456", "purpose": "password_reset" }
  Step 3 — User enters new password:
    POST /auth/password/reset
    Body: { "token": "...", "password": "newpass", "password_confirmation": "newpass" }

TOKEN REFRESH (AUTOMATIC):
  - ApiClient intercepts 401 responses automatically
  - Calls POST /auth/refresh with refresh_token
  - If refresh fails, calls logout() automatically
   c. Navigate to HomeScreen

3. Token storage (use flutter_secure_storage, not SharedPreferences):
   await storage.write(key: 'access_token', value: token);
   await storage.write(key: 'refresh_token', value: refreshToken);

4. The ApiClient automatically:
   - Reads the stored Bearer token for every request
   - On 401 response, calls /auth/refresh automatically
   - On refresh failure, redirects to LoginScreen

UPDATE api_client.dart TOKEN READING:
  The current interceptor reads from a mock token.
  Replace the _getToken() method:

    Future<String?> _getToken() async {
      final storage = FlutterSecureStorage();
      return await storage.read(key: 'access_token');
    }

  And the refresh logic:
    Future<String?> _refreshToken() async {
      final storage = FlutterSecureStorage();
      final refreshToken = await storage.read(key: 'refresh_token');
      if (refreshToken == null) return null;
      final response = await post(
        ApiConfig.refreshToken,
        data: {'refresh_token': refreshToken}
      );
      if (response.isSuccess) {
        final newToken = response.data['access_token'];
        await storage.write(key: 'access_token', value: newToken);
        return newToken;
      }
      return null;
    }

STEP 3: REPLACE MOCK DATA WITH API CALLS
================================================================

AppProvider currently uses _initializeMockData() to populate
all state. To wire real API calls:

3.1 INITIAL LOAD (in AppProvider.initializeMockData):
    Replace with:
      Future<void> initialize() async {
        final userResp = await UserService().getMe();
        if (userResp.isSuccess) {
          _currentUser = userResp.data;
        }
        final chatsResp = await ChatService().getConversations();
        if (chatsResp.isSuccess) {
          _chats = chatsResp.data ?? [];
        }
        final storiesResp = await StoryService().getFeed();
        if (storiesResp.isSuccess) {
          _stories = storiesResp.data ?? [];
        }
        notifyListeners();
      }

3.2 SENDING A MESSAGE (in AppProvider.sendMessage):
    Replace with:
      Future<void> sendMessage(String chatId, String content) async {
        final resp = await ChatService().sendMessage(
          conversationId: chatId,
          content: content,
          type: 'text'
        );
        if (resp.isSuccess && resp.data != null) {
          _chatMessages[chatId] = [
            ...(_chatMessages[chatId] ?? []),
            resp.data!
          ];
          notifyListeners();
        }
      }

3.3 FRIEND REQUESTS:
    In acceptFriendRequest, call:
      await FriendService().acceptRequest(requestId);

3.4 STORIES:
    In addStory, call:
      await StoryService().createStory(mediaUrl: url, type: type);

3.5 USER PROFILE UPDATES:
    In updateUserProfile, call:
      await UserService().updateProfile(displayName: displayName, bio: bio, ...);

STEP 4: ADMIN PANEL API WIRING
================================================================

All admin operations are in lib/api/services/admin_service.dart.
Current state: returns mock data with graceful API fallback.

To wire real API:
  The AdminService methods already attempt real API calls first.
  When the backend is ready, the mock fallback will be bypassed
  automatically because response.isSuccess will be true.

No changes needed to admin screens — they will automatically
use real data once the Laravel backend returns valid responses.

Admin role gating is handled entirely on the Flutter side by
checking provider.currentUser?.staffRole before rendering.
The Laravel backend MUST also validate staff_role on every
/admin/* endpoint (do not trust the client-side check alone).

Creator role gating uses:
  provider.currentUser?.accountStatus == AccountStatus.creator

STEP 5: REAL-TIME FEATURES (WebSockets)
================================================================

The current app uses mock data for messaging. For real-time:

Recommended: Laravel Echo + Pusher or Laravel WebSockets

5.1 Add dependency to pubspec.yaml:
  pusher_channels_flutter: ^2.0.0

5.2 Initialize in AppProvider:
    _pusher = PusherChannelsFlutter.getInstance();
    await _pusher.init(
      apiKey: 'YOUR_PUSHER_KEY',
      cluster: 'YOUR_CLUSTER',
    );

5.3 Subscribe to user's private channel:
    await _pusher.subscribe(
      channelName: 'private-user.${currentUser.id}',
      onEvent: _handlePusherEvent,
    );

5.4 Subscribe to conversation channels:
    For each conversation:
    await _pusher.subscribe(
      channelName: 'private-conversation.${chat.id}',
      onEvent: _handleNewMessage,
    );

5.5 Laravel side (channels.php):
    Broadcast::channel('user.{id}', function ($user, $id) {
        return (int) $user->id === (int) $id;
    });

Events to broadcast from Laravel:
  - App\Events\MessageSent
  - App\Events\UserOnlineStatus
  - App\Events\FriendRequestReceived
  - App\Events\StoryViewed
  - App\Events\NotificationReceived

STEP 6: PUSH NOTIFICATIONS
================================================================

6.1 Firebase Cloud Messaging (FCM) for Android:
    - Add google-services.json to android/app/
    - Add Firebase Flutter SDK to pubspec.yaml
    - Initialize in main.dart before runApp()

6.2 Apple Push Notification Service (APNs) for iOS:
    - Configure APNs certificate in Firebase Console
    - Add GoogleService-Info.plist to ios/Runner/

6.3 Register device token after login:
    FirebaseMessaging.instance.getToken().then((token) {
      if (token != null) {
        DeviceService().registerPushToken(token, platform: 'fcm');
      }
    });

6.4 Handle background messages:
    FirebaseMessaging.onBackgroundMessage(_firebaseMessagingBackgroundHandler);

6.5 Notification types to handle:
    - message:          Navigate to conversation
    - friend_request:   Navigate to friend requests
    - story_reaction:   Navigate to story
    - streak_reminder:  Open app home
    - admin_warning:    Show alert dialog

STEP 8: ERROR HANDLING PATTERNS
================================================================

All service methods return ApiResponse<T> with:
  - isSuccess: bool
  - data: T?
  - message: String?
  - statusCode: int?

Pattern to use in providers and screens:
  final response = await someService.someMethod();
  if (response.isSuccess) {
    // Use response.data
  } else {
    // Show response.message to user
    // Check response.statusCode for specific handling:
    //   401 → redirect to login (handled by interceptor)
    //   403 → show "permission denied"
    //   422 → show validation errors
    //   503 → show maintenance mode screen
  }

Do NOT show raw API error messages to end users.
Map API error codes to user-friendly strings.

STEP 11: SECURITY CHECKLIST
================================================================

Backend (Laravel):
  [ ] Validate staff_role on ALL /admin/* routes server-side
  [ ] Use API rate limiting per route group
  [ ] Validate file uploads (type, size, virus scan)
  [ ] Use HTTPS only in production
  [ ] Set CORS to allow only your app domain
  [ ] Log all admin actions to admin_audit_logs table
  [ ] Hash passwords with bcrypt (Laravel default)
  [ ] Use short-lived access tokens (24h) + refresh tokens (30d)
  [ ] Implement account lockout after failed login attempts
  [ ] Sanitize all user input before storing
  [ ] Use prepared statements / Eloquent ORM (no raw queries)
  [ ] Enable MySQL SSL connections

Flutter App:
  [ ] Store tokens in flutter_secure_storage (not SharedPreferences)
  [ ] Certificate pinning for production API calls
  [ ] Obfuscate release builds (flutter build --obfuscate)
  [ ] Never hardcode API keys in source code
  [ ] Clear tokens on logout
  [ ] Handle token expiry gracefully without data exposure
